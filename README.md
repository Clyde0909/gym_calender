# GYM LOG

계정과 서버 없이 브라우저 기기에 저장하는 영어·한국어·일본어 운동 기록 웹앱. GitHub Pages에서 실행합니다.

## 실행

Node.js 22.12+ 또는 24 사용.

```sh
npm ci
npm run dev
npm test
npm run build
npm run test:e2e
npm run test:pages
```

브라우저 테스트는 시스템 `/usr/bin/chromium`을 사용합니다. 다른 경로는 `CHROMIUM_PATH`로 지정하세요. 설치된 Playwright 브라우저를 사용하려면 설정의 executablePath를 해당 실행 파일 경로로 지정하세요.

## 기능

- 추천 워크아웃 7개, 난이도·주간 횟수 필터, 공개 입문 프로그램 원문 링크
- 날짜별 주간 세트 계획 생성·편집·삭제, 빈 날짜의 요일 세트 자동 로딩
- 120종 운동 라이브러리(기존 60종 + 추가 60종)와 3개 언어 종목 검색, 종목별 한국어·영어·일본어 4단계 자세 안내(준비, 실행, 호흡, 주의사항)
- 월별 캘린더, 날짜별 운동·무게·횟수·세트 완료·메모
- 운동 이름 검색 및 직접 입력, 운동 루틴 저장·불러오기
- 완료 세트의 볼륨 통계와 최근 8주 그래프, 운동 히스토리
- 운동 세션 시작·종료·수행 시간, 기본 90초 자동 휴식 타이머 (설정에서 변경)
- 종목 초성 검색, 부위·기구 필터, 자세 안내
- 루틴 편집·복제·순서·요일별 배치, 이전 기록 재사용, 5×5 템플릿과 규칙 기반 중량 제안
- kg/lbs와 운동 목표 설정, 1RM 계산·성장 기록·3대 운동·부위별 볼륨
- PWA manifest와 버전별 오프라인 정적 파일 캐시
- 하루 사진 1장: 교체 가능, JPG/PNG/WebP/HEIC/HEIF, 최대 25MB 입력, 긴 변 1280px 및 WebP 최대 600KB로 압축 (사진의 원본 화질은 보존하지 않음)
- 날짜별 공유 또는 전체 백업 (사진, 메모, 루틴 포함)
- 공유 문자열 복사·파일 다운로드·지원 기기의 파일 공유
- 가져오기 전에 날짜 충돌 확인, 같은 날짜만 교체하며 나머지 기록 유지
- 별도 로그인·회원관리 없음: 해당 브라우저의 데이터가 사용자의 기록

## 저장과 공유 형식

사진 때문에 localStorage의 작은 용량 제한을 피하기 위해 기기 내 **IndexedDB**에 모든 데이터를 저장합니다. 브라우저 프로필·사이트 원점마다 기록은 분리되며 기기 간 자동 동기화는 없습니다. 저장 실패는 사용자에게 표시하고 메모리 변경도 되돌립니다. 서버에 사용자 데이터·사진·비밀번호를 보내지 않습니다. 브라우저 사이트 데이터 삭제나 기기 분실에 대비해 백업하세요.

기본 공유 형식 `GW3.P.<base91>`은 JSON → LZ-String 1.5.0 (compressToUint8Array) → Base91입니다. 단순 문자 형식 `GW4.P.<base64url>`도 선택할 수 있으며 기존 gzip GW1/GW2 문자열도 계속 복원합니다. 사진은 이미 WebP로 압축하므로 추가 압축 효과가 제한됩니다. 문자열은 사람이 읽는 정보보다 전달 안정성을 우선한 ASCII입니다. 사진이 있는 문자열은 메신저 길이 제한에 걸릴 수 있으므로 `.txt` 파일로 공유하는 것이 좋습니다. 원본 보존을 포기한 사진 압축과 LZ-String을 사용하며 이론적으로 최대 압축률을 보장하지 않습니다.

비밀번호를 설정하면 `GW3.E.<base91>`로 내보냅니다 (단순 문자 옵션은 GW4.E). LZ-String 압축 이후 PBKDF2-SHA256 (310,000회, 무작위 16바이트 salt)로 AES-256-GCM 키를 만들고 무작위 12바이트 IV로 인증 암호화합니다. 비밀번호는 저장·전송하지 않으며 복구할 수 없습니다. 강력한 비밀번호를 별도 채널로 전달하세요. 복호화·압축해제 데이터는 24MiB로 제한하며 형식 검증 후 적용합니다. 로컬 저장소 자체는 암호화하지 않으므로 기기를 공유하는 사람은 브라우저 기록에 접근할 수 있습니다.

HTTPS 또는 localhost와 최신 Chrome/Edge/Firefox/Safari가 필요합니다 (Web Crypto, DecompressionStream, IndexedDB, Canvas). 외부 CDN, API, 런타임 패키지 요청 없이 동작합니다.

## GitHub Pages 배포

1. 저장소 Settings → Pages → Source를 **GitHub Actions**로 설정합니다.
2. `master`에 변경 사항을 push하거나 `Deploy GitHub Pages` 워크플로를 수동 실행합니다.
3. 워크플로는 단위 테스트·정적 빌드 후 Pages에 배포합니다.

상대 asset 경로로 빌드하여 `/gym_calender/` 같은 프로젝트 경로를 지원합니다. 배포 완료 후 Actions 실행 결과와 게시된 주소를 확인하세요.

## 벤치마킹 범위

짐워크 사이트와 제공된 요약 링크는 개발 환경의 네트워크 프록시에서 접근이 제한되었습니다 (CONNECT 403). 제공해 주신 기능 요약을 기준으로 기기 저장·운동 기록 핵심 흐름과 분석·공유 기능을 독립 구현했습니다. 원본 화면/기능의 1:1 일치 여부는 검증하지 않았습니다. 전체 구현 범위와 남은 확장 기능은 [기능 목록](docs/FEATURES.md)을 참조하세요.

## 검증

단위 테스트(`npm test`)와 PC·모바일 브라우저 테스트(`npm run test:e2e`)로 구성되며, 이 문서는 특정 통과 개수를 보증하지 않으므로 최신 결과는 직접 실행해 확인하세요. 라이브러리 테스트는 120종의 개수·이름 유일성, 기존 60종의 순서·이름·부위·기구·번역 호환, 세 언어 4단계 안내의 완전성, 별칭 충돌과 왕복 변환, 검색·초성·필터 조합, 직접 입력 이름 보존, 추가 종목의 브라우저 추가·저장을 확인합니다. `npm run test:pages`는 프로덕션 빌드를 실제 `/gym_calender/` 경로에서 서비스한 뒤 네트워크를 끊고 새로고침·기기 저장·암호화 공유까지 검증합니다.

## 다국어 (i18n)

영어 (`en`), 한국어 (`ko`), 일본어 (`ja`)를 지원합니다. 첫 방문은 브라우저의 기본 언어로 감지하며 `en-US`, `ko-KR`, `ja-JP` 같은 지역 코드를 지원합니다. 다른 언어는 영어로 표시합니다. 상단 언어 선택은 이 브라우저의 localStorage에 저장하여 재방문 시 유지합니다. `?lang=en`, `?lang=ko`, `?lang=ja`로 지정할 수도 있으며, URL에 언어가 있는 상태에서 선택을 변경하면 URL도 갱신합니다. 우선순위는 URL 언어 → 저장한 선택 → 브라우저 기본 언어 → 영어입니다.

메뉴, 입력·접근성 안내, 날짜·숫자, 오류, 확인 대화상자, 공유·복원 메시지와 기본 운동 종목·가이드에 적용합니다. 120종 모두 한국어·영어·일본어 종목명을 가지며, 종목마다 준비 자세(setup), 수행 방법(execution), 호흡(breathing), 주의사항(precautions) 4개 항목 안내를 세 언어로 제공합니다. 종목은 세 언어로 검색할 수 있으며 기본 종목의 내부 식별 이름은 한국어 값을 유지하여 기록·통계·이전 기록 연결이 언어 전환에 영향을 받지 않습니다. 사용자가 작성한 메모, 루틴 이름, 직접 등록한 운동 이름은 번역하지 않습니다. 화면 번역은 `src/translations.json`, 운동 이름과 개별 가이드는 `src/exercises-existing.json`과 `src/exercises-new.json`, 언어 처리와 날�� 포맷은 `src/i18n.js`에 있습니다. 외부 번역 API 없이 오프라인에서도 동작합니다.

## 모바일 집중 운동

모바일 폭에서 운동 시작을 누르면 전체 화면으로 현재 운동·무게·횟수를 크게 표시합니다. 화면 터치로 세트를 완료하고, 휴식이 끝나면 화면·소리·지원 기기의 진동으로 알립니다. 다음 세트는 터치로 시작하며 모든 세트를 마치면 다음 종목으로 이동합니다. 마지막 세트를 마치면 세션을 자동 종료하고 사진 등록 또는 사진 없이 마치기를 선택합니다. 완료한 세트는 즉시 저장하며 집중 화면에서 나가도 기록은 유지됩니다. 같은 탭의 새로고침으로 진행 단계와 휴식 마감 시각을 복원합니다. 연속 터치로 세트를 잘못 완료하지 않도록 짧은 중복 입력 방지 시간을 둡니다.

지원 기기는 운동 중 화면 꺼짐 방지와 브라우저 전체 화면을 사용합니다. 백그라운드 알림 버튼에서 시스템 알림 권한을 요청할 수 있으며 iPhone은 설치된 PWA 등 브라우저 조건이 필요할 수 있습니다. 브라우저나 OS가 탭을 완전히 정지하거나 앱을 종료하면 서버 없는 웹 타이머의 정시 백그라운드 알림은 보장할 수 없습니다. 다시 화면에 돌아오면 마감 시각을 기준으로 즉시 갱신합니다.

HEIC/HEIF는 브라우저 기본 디코더를 우선 사용하고, 지원하지 않으면 번들에 포함된 `heic-to`의 libheif 디코더를 워커에서 실행합니다. 사진을 서버에 업로드하지 않습니다. 기기에서 촬영한 고효율 사진의 MIME 값이 없거나 확장자가 대문자인 경우도 감지합니다. 다중 이미지 파일은 기본 이미지 1장만 사용합니다. 일부 미지원·손상된 변형은 JPEG 내보내기를 안내합니다. HEIC 디코더는 별도 지연 로딩 청크이며 오프라인 캐시에도 포함됩니다.

모바일의 기록 공유는 미리 압축한 파일을 터치 이벤트에서 바로 Web Share API로 전달합니다. 암호화 공유는 백업·공유 화면에서 비밀번호를 설정해 문자열을 생성한 뒤 기기 공유를 누릅니다. 파일 공유가 없으면 짧은 문자열 공유를 사용하고, 긴 사진 포함 데이터는 잘라내지 않습니다. 지원이 없거나 권한을 거부하면 파일 다운로드·복사 대화상자로 전환합니다. 취소는 오류로 표시하지 않습니다.

## 추천과 주간 세트 목록

추천 화면은 공개 운동 자료와 일반적인 분할 방식에 기반한 자체 예시 6개 및 r/Fitness 입문 구성을 참고한 고정 3×5 예시 1개를 제공합니다. 참고한 원문 링크를 표시하며 실시간 코치 서비스나 외부 API 자동 추천은 아닙니다. r/Fitness 원형의 AMRAP·주차 교대·증량 규칙은 이 고정 예시에 자동화하지 않았습니다.

추천에서 생성하거나 내 루틴에서 요일별 저장 루틴을 선택하여 날짜가 있는 주간 계획을 만들 수 있습니다. 주는 월요일부터 일요일이며 선택 날짜가 포함된 주로 정규화합니다. 요일 세트는 계획 자체에서 편집할 수 있고 주간 계획의 세트는 스냅샷으로 저장합니다.

선택한 날짜에 실제 기록이 없다면 해당 주의 요일 세트가 바로 표시됩니다. 입력·완료 체크·운동 시작 시 실제 기록으로 저장합니다. 실제 기록이 있으면 계획 편집·삭제·교체로 변경하지 않습니다. 명시적인 '이 날 계획 불러오기'만 확인 후 세트를 교체합니다. 날짜가 있는 주간 계획이 반복 요일 루틴보다 우선하며, 주간 휴식일은 반복 루틴도 불러오지 않습니다. 전체 백업에는 주간 계획도 포함되며 같은 주의 계획은 가져오기 확인 후 교체됩니다.

운동 이름·분류 참고: [Free Exercise DB](https://github.com/yuhonas/free-exercise-db), public domain / Unlicense, 876종의 공개 데이터를 확인하고 기존 60종을 선별·정리했습니다. 기존 60종의 운동 안내는 자체 작성한 3개 언어 설명입니다. 추가 60종의 이름·분류·안내는 외부 출처로 개별 검증하지 않았으며 외부 자료에서 가져왔다고 표시하지 않습니다.

종목별 안내는 일반적인 자세·호흡 참고용입니다. 일반 웨이트 트레이닝의 기술·호흡 원칙은 [Mayo Clinic 웨이트 트레이닝 안내](https://www.mayoclinic.org/healthy-lifestyle/fitness/in-depth/weight-training/art-20045842)를 안전 참고 자료로 확인할 수 있으나, 각 종목의 안내 문구를 이 자료에서 가져왔거나 승인받았다는 뜻은 아닙니다. 개인별 건강 상태·부상·통증에 대한 의료·트레이너 조언이 아니며 통증이 있으면 운동을 멈추세요. 종목별 사진·시범 영상은 제공하지 않으며 종목 안내는 4개 항목의 텍스트입니다. [공개 r/Fitness 구성 확인 자료](https://github.com/astashov/liftosaur/blob/master/programs/builtin/basicBeginner.md)는 운동 구성·원문 출처 확인에 사용했으며 해당 저장소의 프로그램 실행 코드를 복사하지 않았습니다.

공유 인코딩의 이론적 한계와 실제 사진 포함 길이 비교는 [공유 형식·실측](docs/SHARING.md)을 참고하세요.
