# 공유 문자열 형식과 길이 측정

기본 형식은 `GW3.P.<base91>` (암호화 없음) 또는 `GW3.E.<base91>` (비밀번호 AES-256-GCM)입니다. JSON 문자열 → LZ-String 1.5.0 `compressToUint8Array` → 선택적 암호화 → Base91 순서입니다. 단순 문자 형식은 동일한 LZ-String 데이터를 Base64url로 표현한 `GW4.P.<base64url>` / `GW4.E.<base64url>`입니다. 운동 데이터의 version은 1을 유지합니다.

기존 gzip 기반 GW1 (Base64url), GW2 (Base91) 문자열도 계속 복원합니다. 새 내보내기는 모두 LZ-String을 사용하며 구버전 앱은 GW3/GW4를 읽을 수 없으므로 업데이트해야 합니다. 본문에는 마침표가 포함될 수 있어 헤더만 분리합니다. 암호화는 PBKDF2-SHA256 310,000회, 무작위 salt 16바이트, IV 12바이트 및 AES-256-GCM을 유지하고 전송 버전·모드를 GCM 인증 데이터에 포함합니다.

LZ-String 바이트 형식과 호환되는 제한형 디코더로 복원 문자열의 증가를 제한하며 최종 UTF-8 데이터는 24MiB를 넘을 수 없습니다. 원본 LZ-String 라이선스는 [LZ-STRING-LICENSE.txt](LZ-STRING-LICENSE.txt)에 보존합니다.

## 이론적 상한

OWASP는 압축용 특수문자 알파벳을 정하지 않습니다. 영문 대·소문자 52개 + 숫자 10개 + ASCII 특수문자 32개를 사용할 수 있습니다. 정보량은 `log2(문자 수)` bit/문자입니다.

| 표현                               | 문자 수 | 압축 바이트당 필요한 문자 수 (대규모 데이터 이론치) | Base64 대비 감소 |
| ---------------------------------- | ------: | --------------------------------------------------: | ---------------: |
| Base64                             |      64 |                                               1.333 |             기준 |
| Base91                             |      91 |                                            약 1.229 |          약 7.8% |
| 모든 출력 가능한 ASCII (공백 제외) |      94 |                                            약 1.220 |     최대 약 8.5% |

Base91은 단순 비트 연산으로 처리할 수 있고 94자의 이론치에 가깝습니다. Base91 선택은 LZ-String 결과를 문자로 표현하는 오버헤드를 줄입니다. LZ-String은 반복되는 텍스트에 효과적이지만 이미 압축된 WebP 사진이 포함되면 gzip보다 문자열이 길어질 수 있습니다. 사진의 크기를 더 줄이려면 해상도·화질을 낮춰야 하며 정보 손실이 생깁니다. Unicode의 더 큰 문자집합은 문자 수를 더 줄일 수 있으나 UTF-8 바이트 수는 오히려 커질 수 있고 메신저의 문자 정규화·변경에 영향을 받습니다.

## 실측

720×960 RGB 의사난수 이미지를 Pillow의 WebP quality 65로 저장한 합성 샘플과 동일한 운동 JSON을 사용했습니다. 실제 사용자 사진이나 비밀값을 사용하지 않았습니다. 길이는 헤더를 포함한 ASCII 문자 수이며, 암호화의 무작위 salt/IV 때문에 재측정은 소폭 달라질 수 있습니다.

| 샘플            | Base64 (GW4) | Base91 (GW3) |  감소 |
| --------------- | -----------: | -----------: | ----: |
| session         |          254 |          235 | 7.48% |
| session+photo   |      655,588 |      603,048 | 8.01% |
| encrypted+photo |      655,646 |      604,709 | 7.77% |

동일한 사진 포함 샘플의 기존 gzip+Base91 문자열은 512,002자였으므로 LZ-String 결과(603,048자)는 약 17.8% 더 길었습니다. 이는 이 합성 샘플의 결과이며 모든 기록에 대한 압축률을 보장하지 않습니다.

측정: `node scripts/measure-sharing.mjs path/to/sample.webp`.

Base91에는 따옴표·꺾쇠·앰퍼샌드 등의 문자가 포함됩니다. 앱은 생성 문자열을 textarea.value, 파일, 네이티브 공유 데이터로만 처리합니다. HTML이나 URL에 그대로 삽입하지 마세요. 복사·붙여넣기 시 한 글자도 바꾸지 않고 전달해야 합니다. 사진을 포함하면 여전히 수십만 자가 될 수 있으므로 파일 공유를 권장합니다. 문자열 표현을 바꿔도 비밀번호 암호화의 강도는 바뀌지 않습니다.
