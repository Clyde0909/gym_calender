# 공유 문자열 형식과 길이 측정

기본 형식은 `GW2.P.<base91>` (암호화 없음) 또는 `GW2.E.<base91>` (비밀번호 AES-256-GCM)입니다. JSON → gzip 최고 압축 단계 9 → 선택적 암호화 → Base91 순서입니다. 전송 형식에만 버전을 추가했고 운동 데이터의 version은 1을 유지합니다.

기존 `GW1.P.<base64url>`와 `GW1.E.<base64url>`도 계속 복원합니다. 내보내기에서 호환 형식을 선택하면 GW1로 생성합니다. 구버전 앱으로 보낼 때는 호환 형식을 사용하세요. GW2의 본문에는 마침표가 포함될 수 있으므로 헤더만 분리하고 나머지는 전체 본문으로 처리합니다. 암호화 시 전송 버전·모드를 GCM 인증 데이터에 포함합니다.

## 이론적 상한

OWASP는 압축용 특수문자 알파벳을 정하지 않습니다. 영문 대·소문자 52개 + 숫자 10개 + ASCII 특수문자 32개를 사용할 수 있습니다. 정보량은 `log2(문자 수)` bit/문자입니다.

| 표현                               | 문자 수 | 압축 바이트당 필요한 문자 수 (대규모 데이터 이론치) | Base64 대비 감소 |
| ---------------------------------- | ------: | --------------------------------------------------: | ---------------: |
| Base64                             |      64 |                                               1.333 |             기준 |
| Base91                             |      91 |                                            약 1.229 |          약 7.8% |
| 모든 출력 가능한 ASCII (공백 제외) |      94 |                                            약 1.220 |     최대 약 8.5% |

Base91은 단순 비트 연산으로 처리할 수 있고 94자의 이론치에 가깝습니다. 이 변경은 gzip의 압축률을 바꾸는 것이 아니라 그 결과를 문자로 표현하는 오버헤드를 줄입니다. 이미 압축된 WebP 사진은 gzip으로 크게 줄어들지 않습니다. 사진의 크기를 더 줄이려면 해상도·화질을 낮춰야 하며 정보 손실이 생깁니다. Unicode의 더 큰 문자집합은 문자 수를 더 줄일 수 있으나 UTF-8 바이트 수는 오히려 커질 수 있고 메신저의 문자 정규화·변경에 영향을 받습니다.

## 실측

720×960 RGB 의사난수 이미지를 Pillow의 WebP quality 65로 저장한 합성 샘플과 동일한 운동 JSON을 사용했습니다. 실제 사용자 사진이나 비밀값을 사용하지 않았습니다. 길이는 헤더를 포함한 ASCII 문자 수이며, 암호화의 무작위 salt/IV 때문에 재측정은 소폭 달라질 수 있습니다.

| 샘플            | Base64 (GW1) | Base91 (GW2) |  감소 |
| --------------- | -----------: | -----------: | ----: |
| session         |          261 |          241 | 7.66% |
| session+photo   |      555,093 |      512,002 | 7.76% |
| encrypted+photo |      555,152 |      512,013 | 7.77% |

측정: `node scripts/measure-sharing.mjs path/to/sample.webp`.

Base91에는 따옴표·꺾쇠·앰퍼샌드 등의 문자가 포함됩니다. 앱은 생성 문자열을 textarea.value, 파일, 네이티브 공유 데이터로만 처리합니다. HTML이나 URL에 그대로 삽입하지 마세요. 복사·붙여넣기 시 한 글자도 바꾸지 않고 전달해야 합니다. 사진을 포함하면 여전히 수십만 자가 될 수 있으므로 파일 공유를 권장합니다. 문자열 표현을 바꿔도 비밀번호 암호화의 강도는 바뀌지 않습니다.
